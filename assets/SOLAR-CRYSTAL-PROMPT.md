# Cristal solaire — proposition 1

Sprite créé avec l’outil intégré **imagegen**, d’après le cristal n° 1 choisi par l’utilisateur. Source RGBA conservée : `solar-crystal-v1.png`. Le corps facetté est commun à toutes les poses pour éviter les variations de silhouette et les erreurs d’ancrage.

Le jeu prépare 48 poses sur une boucle de 1,6 seconde : lumière intérieure pulsée, halo doré et trois petites braises qui montent et s’éteignent. Le cristal flotte de ±5 unités sur le même temps interpolé que la simulation ; chaque objet possède un décalage de phase. La pause fige le flottement et la pulsation. Les images sont préparées avant la partie dans un seul atlas natif de 576 × 432 pixels, également préchargé sur le GPU ; aucun chargement, redimensionnement ou calcul de particule du cristal pendant le rendu. Le HUD utilise le même sprite, sans flottement.

Les 52 emplacements, la zone de collecte et la recharge restent identiques : +10 points par ramassage unique, avec la réserve plafonnée à 100. Les effets de ramassage existants restent actifs. Aperçu : `python preview_crystal.py --native-check`, vidéo `output/solar-crystal-demo.mp4`, rapport `output/solar-crystal-validation.json`.
